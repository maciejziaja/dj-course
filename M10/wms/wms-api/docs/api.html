WMS API (Warehouse Management System) (2.0.0)

Download OpenAPI specification:

API for warehouse management.

Two generations of endpoints live side by side and they do not share conventions - the contract documents both as they actually behave:

  • Legacy (/employees, /contractors, /payments, /storage, /warehouse/{id}) - bare arrays, no pagination, {"error": "..."} on failure, and timestamps rendered by Flask's default JSON encoder as RFC 1123 HTTP dates (Wed, 11 Dec 2024 06:50:57 GMT).
  • Topology (/locations, /warehouses, /zones, /aisles, /racks, /shelves) - paginated {items, page, limit, total} envelopes, a {"error": <code>, "message": <text>, ...} envelope on failure, and timestamps as naive ISO-8601 (2026-08-27T12:13:55.537725, no offset).

Neither timestamp rendering is RFC 3339, so neither is declared as format: date-time; both are pinned with an explicit pattern instead. See the HttpDate and NaiveDateTime schemas.

This document is enforced at runtime by openapi-core (see src/openapi_guard.py): requests are validated before the handler runs and responses before they leave the process.

Shelves

The leaf level - flat catalogue, single-shelf CRUD and bulk patch.

The flat shelf catalogue

The one filter grammar in this API - every other endpoint addresses by id. String filters are case-insensitive ILIKE, so % works as a wildcard.

query Parameters
page
integer [ 1 .. 1000000 ]
Default: 1

1-based page number. The upper bound exists so that (page - 1) * limit stays inside the integer range Postgres can take as an OFFSET - without it a large enough page number reaches the database and fails there.

limit
integer [ 1 .. 500 ]
Default: 50

Page size.

warehouse
integer <int32>

Exact-match filter on warehouse id.

zone
string <= 16 characters ^[^\u0000-\u001F\u007F]*$

ILIKE filter on zone code.

aisle
string <= 16 characters ^[^\u0000-\u001F\u007F]*$

ILIKE filter on aisle label.

rack
string <= 16 characters ^[^\u0000-\u001F\u007F]*$

ILIKE filter on rack label.

level
string <= 8 characters ^[^\u0000-\u001F\u007F]*$

Exact-match filter on shelf level.

code
string <= 64 characters ^[^\u0000-\u001F\u007F]*$

ILIKE filter on the composed path, e.g. BULK-A01-%.

max_weight_gte
number >= 0

Only shelves whose declared capacity in kg is at least this.

max_volume_gte
number >= 0

Only shelves whose declared capacity in m3 is at least this.

Patch many shelves at once

Takes explicit ids, never a filter - an accidental "update all" is not expressible. All or nothing: one unknown id and nothing is written.

level is deliberately not patchable in bulk: it is unique per rack, so setting the same level on many shelves could only end in a conflict.

header Parameters
X-Request-Id
string <uuid>

Optional correlation id, echoed into the server log line for this request. Must be a UUID when present.

Request Body schema: application/json
required
ids
required
Array of integers <int32> [ 1 .. 5000 ] items [ items <int32 > ]
required
object (ShelfBulkPatchBody) non-empty

level is deliberately absent - it is unique per rack.

number or object (WeightInput)

A weight. A bare number means kilograms. Explicit units are normalised to kg on write and always read back as kg.

One of
( 0 .. 1000000000 ]
number ( 0 .. 1000000000 ]

Kilograms.

number or object (VolumeInput)

A volume. A bare number means cubic metres. Explicit units are normalised to m3 on write and always read back as m3.

One of
( 0 .. 1000000000 ]
number ( 0 .. 1000000000 ]

Cubic metres.
